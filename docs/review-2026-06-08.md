## 🔴 Critical

### 1. Daemon has no inbound auth, Origin check, or DNS-rebinding protection
- **Where:** `src/mcp/server.ts:112` (binds `127.0.0.1`), `:141` (reads only
  `mcp-session-id`), `:148` (transport built without
  `enableDnsRebindingProtection`/`allowedHosts`).
- **Risk:** Loopback binding stops remote networks but not a web page the user
  visits — any site can `fetch('http://127.0.0.1:3848/mcp', …)` and drive every
  tool (`knowledge_store`, `llm_chat`, `cloud_sync_config_set`, `llm_config_set`,
  indexing) using the privileged Lore bearer token. This amplifies #2–#4.
- **Fix:** Require a bootstrap bearer token on `/mcp` (constant-time compare),
  validate `Origin` against an allowlist (Tauri app origin + dev URL), set
  `enableDnsRebindingProtection` with `allowedHosts: ['127.0.0.1:3848','localhost:3848']`.

### 2. Proxies speak cleartext `http` to `https` cloud endpoints (port 80)
- **Where:** `src/mcp/knowledgeProxy.ts:20` (`node:http` only), `:85`,`:111`
  (`port: u.port || 80`); same in `workspaceProxy.ts` and `loreClient.ts:110`.
- **Risk:** When cloud sync is on, `context.ts` routes these to `cloudMcpUrl`
  (`https://…`), so the `Authorization: Bearer <token>` header goes out in
  cleartext to the wrong port.
- **Fix:** Select `https`/`http` from `u.protocol`, default 443/80, refuse to
  send a token over plaintext to any non-loopback host. Centralize in one helper.

### 3. Local bootstrap token exfiltrated to cloud host on misconfig
- **Where:** `src/mcp/context.ts:50` — `token: cs.apiKey ?? token`.
- **Risk:** Enable cloud sync but forget the cloud key → the local
  high-privilege bootstrap token (`~/.groundfloor/atlas/auth.token`) is sent to
  the remote `cloudMcpUrl` (and, per #2, in cleartext).
- **Fix:** Fail closed — if `cloudSync.enabled` and no `cs.apiKey`, error out.
  Never substitute the local token for cloud calls.

### 4. `cloudMcpUrl` / `ollamaUrl` / `loreBinPath` are config-controllable → SSRF + cred redirection + token-bearing subprocess
- **Where:** `config.ts:189-204` (no host allow-listing); `cloud_sync_config_set`
  / `llm_config_set` accept raw URLs; `sidecar/loreSidecar.ts` spawns
  `node <loreBinPath>` with `LORE_AUTH_TOKEN` in env from an unvalidated path.
- **Risk:** Because of #1 these are remotely settable — a web page can point the
  token at an attacker host and trigger a recall, or (with config write) choose
  which binary launches with the Lore token.
- **Fix:** Allow-list cloud hosts (`*.groundfloor.io`, https only; reject
  loopback/metadata IPs); restrict `ollamaUrl` to loopback; canonicalize
  `loreBinPath` under an expected install dir; pass the token via fd/0600 file,
  not inherited env.

### 5. Shutdown orphans the Lore child if MCP close throws
- **Where:** `src/daemon.ts:124-131` — `await handle.close()` runs before
  `sidecar.close()` in the same `try`; a rejection jumps to `catch` → `exit(1)`
  with Lore still alive and port 3847 bound, so the next start refuses to manage it.
- **Fix:** `try { await handle.close() } finally { sidecar?.close() }`.

### 6. `httpPost` has no timeout against a `maxSockets: 4` pool
- **Where:** `src/loreClient.ts:106` (no `req.setTimeout`/`AbortController`),
  pool at `:81`.
- **Risk:** Every write (CLI index + watcher re-index) awaits this; a stalled
  Lore hangs the request forever, and 4 stuck requests exhaust the pool and
  block all writes.
- **Fix:** `req.setTimeout(30_000, () => req.destroy(new Error('lore write timeout')))`,
  mirroring the daemon's `probeLoreHealth`.

## 🟠 High

### 7. Watcher writes node IDs that never reconcile with the full index
- **Where:** `src/fileWatcher.ts:213` calls `parseFile(absFile)` with no
  `repoRoot` → `parser/index.ts:112` sets `path` to the absolute path; the CLI
  passes `repoRoot` and uses repo-relative paths. `repo` is also just
  `basename(dirname(absFile))` (`:219`).
- **Risk:** Node IDs derive from `file.path`, so every re-index creates duplicate
  orphan nodes instead of updating originals. Incremental updates diverge from
  the initial index.
- **Fix:** Thread the watched root through as `repoRoot`; derive `repo` like the
  CLI (`repoForRoot`).

### 8. Watcher indexes `node_modules`/`.git`/`dist`; new `BatchWriter` per file
- **Where:** `src/fileWatcher.ts:267` (extension-only filter, unlike `walker.ts`),
  `:227` (new `BatchWriter` per file).
- **Risk:** A recursive watch + one `npm install` schedules thousands of
  re-index jobs and floods Lore with junk; per-file BatchWriter defeats batching
  and silently swallows per-node failures.
- **Fix:** Reuse the walker's `DEFAULT_SKIP_DIRS`/ignore matcher; hoist one
  long-lived `BatchWriter`; treat `errors.length > 0` as a re-queue.

### 9. `llm_chat` sends repo/knowledge context to an external provider with no redaction/consent
- **Where:** `src/mcp/tools/llmChat.ts` — embeds `context` verbatim, POSTs to
  OpenAI/Anthropic; no size cap on input, no opt-in gate.
- **Fix:** Default cloud providers off (prefer local Ollama), gate behind
  explicit opt-in, add a redaction/size pass.

### 10. API keys persisted plaintext, no explicit mode
- **Where:** `config.ts:232-233`,`260-261` — `mkdirSync`/`writeFileSync` with no
  `mode`; keys land in `config.json` relying on incidental umask.
- **Fix:** Write `{ mode: 0o600 }` / `mkdir 0o700`, `chmod` existing files;
  ideally OS keychain.

### 11. Tauri CSP disabled; unused shell capability
- **Where:** `atlas-ui/src-tauri/tauri.conf.json:26` (`"csp": null`);
  `capabilities/default.json` grants unused `shell:allow-open`.
- **Fix:** Set a strict CSP scoped to the daemon origin; drop `shell:allow-open`.

### 12. Shim refactor dropped per-tool input validation
- **Where:** `src/mcp/allTools.ts` — forwards `args as never`; runners read
  `args.symbol`/`args.limit` unchecked; advertised JSON Schema is advisory only;
  `limit`/`max` unbounded.
- **Fix:** Validate `args` against each tool's schema in `ToolRegistry.invoke`;
  clamp `limit` (e.g. `min(n, 500)`).

## 🟡 Medium
- **13** Unbounded watcher concurrency — branch switch fans out N concurrent
  re-index promises, no per-file serialization (`fileWatcher.ts:243`).
- **14** Raw upstream error bodies echoed to MCP callers (`server.ts:101`,
  `llmChat` catch) — info disclosure.
- **15** Sidecar `restartCount` never resets → 3 lifetime blips permanently
  disable Lore management; crashes wait up to 5 min for the watchdog
  (`loreSidecar.ts:120`).
- **16** Checkpoint rewrites the full file-map per batch + re-stats each file →
  O(n²)-ish I/O on large repos (`cli.ts:228`).
- **17** No `EADDRINUSE` handling for the Groundfloor Atlas port; double-start prints a raw
  stack and (after a sidecar spawn) can orphan Lore (`daemon.ts`).
- **18** Confirm `vite "^8.0.0"` (`atlas-ui/package.json`) resolves to an
  intended published version.

---

## ✅ What's good
- Registry/shim split is clean and crash-safe — layered try/catch means no tool
  can take down the transport; all 26 tools have unique names.
- Config validation, atomic checkpoint writes (temp+rename), mtime+size
  fingerprinting — well done.
- Lore-port probing for safe migration is thoughtful.
- UI is clean where it counts — no `dangerouslySetInnerHTML`, untrusted content
  goes through React text nodes / `JSON.stringify`, keys never hit `localStorage`
  or console, deps mostly current.

## Suggested order of attack
The four criticals collapse into one fix with leverage: **authenticate `/mcp`
(#1)** — that neutralizes the remote exploitability of #3/#4 and most of the
LLM-exfil concern. Then:
1. #1 — auth + Origin + DNS-rebinding on `/mcp`
2. #2/#3 — http/https transport + no-token-over-plaintext
3. #7 — watcher path-ID bug (else incremental indexing is quietly broken)
4. #5/#6 — the two reliability one-liners (finally-block, write timeout)
5. #10/#11 — secrets-to-keychain + CSP
